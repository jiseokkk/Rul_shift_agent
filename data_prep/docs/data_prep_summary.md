# 데이터 준비 단계 정리 — 오염 시나리오 데이터셋과 성능 저하 라벨

작성 2026-09-17. 대상: `agent_RUL/data_prep/` (grid v3, `configs/label.yaml` locked).
설계 원문은 `docs/preparation_plan_final.md`, 검증·개정 이력은 이 문서 5~6절.

---

## 1. 목적과 원칙

LLM 에이전트가 배포된 RUL 모델의 **출력 신뢰성 상실**을 탐지하는지 실험하기 위한 데이터를 만든다.
센서 오염이 들어간 궤적, 그 궤적에 대한 RUL 모델 출력, 그리고 "이 cycle에서 모델 출력이 오염에 의해 교란되었는가"의 정답 라벨이 산출물이다.

세 원칙
1. 모델은 clean 데이터로만 학습한다. 오염본은 추론에만 쓴다.
2. 라벨은 정답 RUL이 아니라 **같은 모델의 clean 예측과의 차이**(counterfactual delta)로 만든다.
3. 라벨은 오프라인 정답이므로 미래 정보를 써도 된다. 에이전트는 인과적으로만 판단한다.

## 3. 오염(shift) 주입

원본 스케일에서 τ_s 이후 cycle의 대상 센서에만 적용. σ_r, μ_r는 모델 정규화 통계와 같은 값.
따라서 bias α는 정규화 공간에서 정확히 α만큼의 이동이다.

| 유형 | 식 | grid v3 파라미터 |
|---|---|---|
| bias | x ← x + d·α·σ_r | α ∈ {0.3, 0.5, 0.75, 1.0}, d ∈ {+,−} |
| gain | x ← μ_r + (x − μ_r)(1 + d·α) (평균 중심) | pos α ∈ {0.5, 1.0, 1.5, 2.0}, **neg α ∈ {0.25, 0.5, 0.75}** |
| noise | x ← x + ε, ε ~ N(0, (β·σ_r)²) | β ∈ {1, 2, 3}, seed 기록 |
| stuck | x ← x(τ_s) | — |
| multi_C | 3센서 각각 + sign_deg(s)·α·σ_r(s) (열화 방향 일관) | α ∈ {0.3, 0.5} |
| multi_I | 3센서 각각 + sign(s)·α·σ_r(s), 부호 무작위(±sign_deg 제외) | α ∈ {0.3, 0.5} |

- 센서: T24, T30, T50 (raw 컬럼 6, 7, 8). **T30은 음성 대조군** — 모델 민감도가 T24의 0.22배라 센서가 변해도 출력이 거의 안 움직인다.
- 주입 시점: τ_s = round(t0 + p·(T_u − t0)), t0 = 45 + N = 55 (N=10, `configs/agent.yaml`), p ∈ {0.2, 0.4, 0.6, 0.8}.
  모든 unit에서 τ_s ≥ 55 → 에이전트는 오염 전에 최소 10 cycle의 정상 예측을 본다. cycle 1~54는 모든 시나리오에서 clean.
- 규모: **244 시나리오/unit × 20 unit = 4,880**. (bias 96 + gain 84 + noise 36 + stuck 12 + multi_C 8 + multi_I 8 = 244)
- 파일: `data/shifted/FD001/u{unit}/{scenario_id}.parquet` — 원본과 같은 26컬럼, **cycle 1~T_u 전체 궤적**, 메타(τ_s, σ_r, seed) 포함.
- scenario_id: `{type}_{sensor}_{param}_{dir}_p{timing}` 예 `bias_T24_a1.0_neg_p0.2`.

### 주입 크기의 의미 (train 80 기준)

| 센서 | σ_r | cycle 간 잡음 | 수명 전체 변화 | bias α=0.3 | bias α=1.0 |
|---|---|---|---|---|---|
| T24 | 0.50 | 0.30 | 1.10 | 잡음의 0.5배 | 수명변화의 0.46배 |
| T30 | 6.13 | 4.01 | 13.2 | 0.5배 | 0.46배 |
| T50 | 9.03 | 4.02 | 22.3 | 0.7배 | 0.40배 |

α가 σ_r 단위라 세 센서에서 잡음 대비·열화 대비 비율이 거의 같다. α=0.3은 한 cycle로는 안 보이고, α=1.0은 엔진이 평생 겪는 변화의 절반을 한 번에 넣는 큰 고장이다.

### 방향(과대/과소 예측)

세 센서 모두 열화 시 값이 오른다(sign_deg = +1). 센서를 올리는 오염 → 더 열화돼 보임 → RUL **과소** 예측, 내리는 오염 → **과대** 예측.

| 유형 | 방향 | τ_s 이후 (ỹ − ŷ) 평균 (T24 / T50) |
|---|---|---|
| bias neg | 과대(건강해 보임) | +5.3 / +4.6 |
| bias pos | 과소 | −4.8 / −3.7 |
| stuck | 과대(열화 진행이 안 보임) | +4.6 / +3.4 |
| noise | 과소(모델이 비대칭 반응) | −4.2 / −4.8 |
| multi_C | 과소 | −6.0 |
| multi_I | 혼합(의도) | −0.2 |
| gain | **수명 중 반전**: 센서가 fleet 평균 아래(초반)와 위(후반)에서 미는 방향이 바뀜 | pos: 초반 +1~+2.5, 후반 −4.7~−7.5 |

방향 축 분석에서 gain은 제외하고 별도 성격으로 다룬다.

## 4. 성능 저하 라벨

### 4-1. 정의

```
δ(t) = |ỹ(t) − ŷ(t)|,  t ∈ [45, T_u]     ỹ: 오염 예측, ŷ: 같은 모델의 clean 예측 (seed 529)
assert: τ_s 이전 δ == 0 (전 시나리오 통과)
```

히스테리시스 k-of-m 상태 머신 (`src/label/hysteresis.py`)
- 진입: 최근 m=7 중 k=5개가 δ > θ_high → 첫 초과 cycle까지 역방향 채우기, 그 시점이 **τ_d**
- 복귀: 최근 7 중 5개가 δ ≤ θ_low = 0.5·θ_high → 복귀 허용 (수명 말기에 두 예측이 0으로 수렴하면 δ가 사라짐)
- 출력: `labels/FD001/state/{theta}/u{unit}/{scenario_id}.parquet` [time, delta, label, state, theta_high, theta_low]

| θ | 값 | 근거 |
|---|---|---|
| **theta_primary** | 9.399 | clean 예측의 인접 cycle 변화 V1의 95 percentile (seed 529, hold-out). clean-only 대조(seed 530 vs 529) cycle 양성률 3.5% ≤ 5% 통과 |
| theta_alt1 | max(0.2·ŷ, 9.399) | 상대 기준 + 바닥 |
| theta_alt2 | 13.33 | test RMSE |

### 4-2. eval_mask (채점 전용, 라벨 불변)

수명 말기에 ŷ, ỹ가 모두 0 근처로 수렴하면 오염이 계속돼도 δ가 소멸해 라벨이 1→0으로 복귀한다(저하 시나리오의 87%).
이 구간의 라벨 0은 정의상 옳지만 에이전트는 clean 예측을 못 보므로 맞출 수 없다.
→ 시나리오별 **최종 복귀(재진입 없음) 이후 구간**을 `labels/FD001/meta/eval_mask.csv`의 `mask_from_cycle`로 기록하고 cycle 단위 채점에서 제외한다. 마스크 적용 결과를 주 결과, 미적용을 부록으로 둘 다 보고한다.

### 4-3. 라벨의 뜻 (중요)

라벨 1은 **"오염 때문에 모델 출력이 clean 대비 θ 이상 벗어난 상태"**(출력 신뢰성 상실, 예측 교란)이다. **"정답 대비 정확도가 나빠진 상태"가 아니다.**

- 라벨 1 cycle 중 정답 RUL 기준 오차가 커진 것 72.4%, **오히려 정확해진 것 27.6%**. clean 모델이 RUL 25~125 구간에서 +3~5 낙관 예측하는 편향이 있어, 센서를 올리는 오염(과소 방향)이 이를 상쇄하기 때문.
- 정확도 기준을 라벨로 쓰면 라벨이 모델의 편향에 종속되고 에이전트가 맞출 수 없어, 교란 기준을 유지하고 이름을 명확히 한다. 정확도 기준은 보조 지표로 병기.
- 삼각부등식으로 |오염 오차 − clean 오차| ≤ δ이므로, 교란이 없으면(라벨 0) 성능 저하도 없다. 교란은 저하의 필요조건.
