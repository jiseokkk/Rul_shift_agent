# 연구계획서

**연구 제목 (국문)**: RUL 예측 모델의 성능 저하 탐지 및 출력 신뢰성 판단을 위한 LLM 에이전트 연구

**연구 제목 (영문)**: An LLM Agent for Detecting Performance Degradation and Assessing Output Reliability of RUL Prediction Models

---

## 1. 연구의 배경 및 필요성

### 1.1 배경

항공기 엔진, 발전 터빈, 반도체 장비처럼 고장 비용이 큰 설비에서는 센서 데이터로부터 잔여수명(Remaining Useful Life, RUL)을 예측하는 모델이 예지보전(predictive maintenance)의 핵심 구성 요소로 쓰이고 있다. 최근 딥러닝 기반 RUL 모델은 공개 벤치마크에서 높은 정확도를 보이며, 실제 현장에도 배포되기 시작했다.

그러나 이 모델들은 학습 시점에 관측된 **정상 센서 데이터**를 전제로 만들어진다. 실제 운영에서는 센서 자체가 고장 나거나 성능이 변한다. 편향(bias, 일정 값이 더해짐), 감도 변화(gain, 변화 폭이 커지거나 작아짐), 잡음 증가(noise), 값 고착(stuck, 같은 값이 계속 출력됨), 여러 센서의 동시 이상 등이 대표적이다. 이런 입력 오염이 발생하면 RUL 모델은 그것을 인식하지 못한 채 **그럴듯한 숫자를 계속 출력**한다. 운영자는 화면에 표시된 "남은 수명 87 사이클"이 정상 입력에서 나온 것인지, 오염된 입력에 끌려간 것인지 구분할 수 없다. 오염이 수명을 실제보다 길게 보이게 만들면 정비가 늦어져 고장으로 이어지고, 짧게 보이게 만들면 불필요한 정비로 비용이 발생한다.

### 1.2 기존 접근의 한계

이 문제에 대한 기존 접근은 두 갈래로 나뉜다.

첫째, **통계적 공정관리 및 센서 고장진단(FDI)** 기법은 센서 값의 통계적 이상을 탐지한다. 관리도, CUSUM, 다변량 T² 통계량 등이 오래 연구되었고 센서 이상 자체는 잘 잡는다. 그러나 이 기법들은 "그 센서 이상이 **예측 모델의 출력에 실제로 영향을 주는가**"에는 답하지 않는다. 예측 모델은 모든 센서를 같은 비중으로 쓰지 않는다. 모델이 거의 참조하지 않는 센서가 오염되면 출력은 변하지 않으며, 이때 경보는 오경보가 된다. 반대로 모델이 민감한 센서의 작은 오염은 출력을 크게 흔들 수 있다.

둘째, **예측 모델 자체의 불확실성 추정**(MC dropout, 앙상블 등)은 출력 측 신호를 제공한다. 그러나 예비 실험에서 확인한 바, 이 신호는 오염이 없어도 설비의 수명 단계에 따라 자연스럽게 변한다. 단독으로 쓰면 오경보가 많다.

즉 입력 측 증거(센서 통계)와 출력 측 증거(모델 출력의 거동)를 **결합해 해석**하는 층이 필요하다. "센서 T30이 평소와 다르게 움직이지만 이 모델은 T30에 둔감하므로 출력은 여전히 믿을 수 있다", "센서 T24의 편차가 지속되고 모델 출력의 불확실성도 함께 커졌으므로 출력을 신뢰할 수 없다" 같은 판단은 여러 증거의 조합과 맥락 해석을 요구한다. 이런 판단은 고정된 임계값 규칙으로 쓰기 어렵고, 대규모 언어모델(LLM) 기반 에이전트가 적합한 후보다.

### 1.3 근본적 어려움: 배포 중에는 정답을 알 수 없다

이 연구가 다루는 문제의 근본적 어려움은 **운영 중에는 정답 RUL을 알 수 없다**는 점이다. 설비가 실제로 고장 나기 전까지 남은 수명이 얼마였는지는 아무도 모른다. 따라서 "모델 성능이 저하되었다"를 "정확도가 떨어졌다"로 정의하면, 그 정의는 배포 환경에서 검증할 수 없는 양이 된다.

본 연구는 이 문제를 정면으로 다룬다. 성능 저하를 **"오염이 없었다면 같은 모델이 냈을 예측(counterfactual)과 현재 출력의 차이"**로 정의한다. 이 정의는 실험실에서는 정확히 계산할 수 있어 정답 라벨을 만들 수 있고, 배포 환경에서 에이전트가 판단해야 하는 것("이 출력이 오염에 끌려가 있는가")과 일치한다. 이 정의를 바탕으로 벤치마크와 평가 체계를 구축하고, 그 위에서 LLM 에이전트의 탐지 능력을 실증하는 것이 본 연구의 골자다.

## 2. 연구 목표

본 연구의 목표는 다음 네 가지다.

1. **벤치마크 구축**: 공개 RUL 데이터셋과 공개 RUL 모델 위에 체계적인 입력 오염 시나리오를 주입하고, counterfactual 기준의 성능 저하 정답 라벨을 부여한 벤치마크를 만든다.
2. **에이전트 설계·구현**: 배포 환경에서 관측 가능한 정보(센서 이력, 모델 출력 이력, 모델 불확실성)만을 증거로 받아, 매 운용 주기마다 "현재 모델 출력을 신뢰할 수 있는가"를 판정하고 근거를 제시하는 LLM 에이전트를 만든다.
3. **평가 체계 확립과 실증**: 시간 단위(매 주기의 상태를 맞히는가)와 사건 단위(저하 시작을 얼마나 빨리 잡는가)의 두 축으로 에이전트를 평가하고, 규칙 기반 판정기 및 무판단 기준선과 비교한다.
4. **설계 요인 규명**: 에이전트에게 주는 증거의 종류(입력 측 / 출력 측 / 결합), 정상 기준의 출처(설비 자기 이력 / 정상 fleet), 도구 호출 방식(고정 / 동적)이 탐지 성능에 미치는 영향을 절제 실험으로 밝힌다.

## 3. 선행 연구와 본 연구의 차별성

- **RUL 예측**: C-MAPSS 데이터셋(Saxena et al., 2008)을 중심으로 RNN, CNN, Transformer 기반 모델이 다수 제안되었다. 이 연구들은 정확도 향상이 목표이며, 배포 후 입력 오염에 대한 모델의 거동은 다루지 않는다.
- **센서 고장진단(FDI)·통계적 공정관리**: 다변량 통계량과 기여도 분석으로 이상 센서를 식별한다(Qin, 2003 등). 대상은 센서·공정이며, 하류의 예측 모델이 그 이상에 어떻게 반응하는지는 범위 밖이다.
- **데이터셋 변화 탐지(dataset shift, concept drift)**: 입력 분포의 변화나 예측 분포의 변화로 모델 감시를 시도한다(Gama et al., 2014; Rabanser et al., 2019). 대체로 집단 수준·배치 수준의 분포 비교이며, 개별 설비의 스트림에서 매 주기 판정하는 문제와는 설정이 다르다.
- **LLM 에이전트의 시계열 이상 탐지**: 최근 LLM을 시계열 분석 도구와 결합하는 시도가 늘고 있으나, 대부분 이상 자체의 탐지가 목표이고 "하류 모델의 출력 신뢰성"을 판정 대상으로 삼은 연구는 드물다.

본 연구의 차별성은 세 가지다. (1) 판정 대상을 "센서 이상"이 아니라 "**모델 출력의 신뢰성**"으로 두고, 이를 counterfactual 차이로 정의해 정답을 만들었다. (2) 모델이 둔감한 센서의 오염을 **음성 대조군**으로 포함해, 에이전트가 "센서 이상"과 "모델 저하"를 구분하는지를 직접 시험한다. (3) 에이전트가 볼 수 있는 정보를 배포 환경과 같게 제한하고 이를 코드 수준에서 강제한다.

## 4. 연구 내용 및 방법

### 4.1 벤치마크 구축 (완료)

**데이터와 모델.** NASA C-MAPSS FD001(터보팬 엔진 100대, 고장까지의 전 수명 궤적, 단일 운전조건)을 사용한다. 수명 분포를 층화하여 80대로 공개 Transformer 기반 RUL 모델을 학습하고, 20대를 평가용으로 보존한다. 모델은 45주기 길이의 센서 창을 입력으로 받아 RUL을 출력하며, 시험 세트 RMSE 13.3으로 원 논문 수준을 재현한다.

**오염 시나리오.** 평가용 20대 각각에 아래 6종의 오염을 센서 3종(T24, T30, T50), 강도 여러 단계, 주입 시점 4개(수명의 20/40/60/80%)로 조합하여 주입한다. 모든 오염은 원본 단위에서 주입 시점 이후 주기에만 적용되며, 주입 전 구간은 원본과 동일하다.

| 유형 | 내용 | 강도 |
|---|---|---|
| bias | 일정 값을 더함 (± α·σ) | α = 0.3, 0.5, 0.75, 1.0 |
| gain | 평균을 중심으로 변화 폭을 확대 / 축소 | 확대 0.5~2.0, 축소 0.25~0.75 |
| noise | 정규 잡음을 더함 (β·σ) | β = 1, 2, 3 |
| stuck | 주입 시점의 값으로 고정 | — |
| multi_C / multi_I | 3센서 동시 (열화 방향 일관 / 무작위 부호) | α = 0.3, 0.5 |

여기서 σ는 학습 데이터에서 계산한 센서별 표준편차로, 모델의 정규화 척도와 같다. 엔진당 244개, **총 4,880개 시나리오**가 만들어진다. 센서 T30은 모델의 민감도가 T24의 약 1/5에 불과해, 센서가 변해도 출력이 거의 움직이지 않는 **음성 대조군** 역할을 한다.

**성능 저하 라벨.** 각 시나리오에 대해 오염 입력에 대한 예측 ỹ(t)와 같은 모델의 clean 입력에 대한 예측 ŷ(t)를 모두 계산하고, δ(t) = |ỹ(t) − ŷ(t)|를 정의한다. δ가 모델의 자연 변동(clean 예측의 인접 주기 변화)의 95% 지점인 9.4주기를 넘는 상태가 최근 7주기 중 5주기 이상 지속되면 저하 시작으로 보고, 첫 초과 시점까지 거슬러 라벨 1을 부여한다. 반대로 7주기 중 5주기에서 δ가 4.7 아래로 내려오면 저하 종료로 본다. 이 규칙으로 주기별 0/1 라벨과 저하 시작 시점 τ_d가 정해진다. 저하로 판정된 시나리오는 1,345개(27.6%)이다.

이 라벨은 **"모델 출력이 오염에 끌려가 신뢰할 수 없는 상태"**를 뜻하며, 정답 대비 정확도 하락과는 구별된다. 실제로 라벨 1인 주기 중 28%는 오염이 모델의 낙관 편향을 우연히 상쇄해 정답에 더 가까워진 경우였다. 정확도 기준을 쓰지 않는 이유는, 그렇게 하면 라벨이 모델 고유의 편향에 종속되어 같은 오염이 모델마다 저하/개선으로 갈리고, 배포 환경에서는 에이전트가 답할 수 없는 양이 되기 때문이다.

**검증.** 4,880개 전 시나리오에 대해 주입 크기·시점의 정확성, 예측의 재현성, 라벨의 독립 재계산 일치를 확인했다. 또한 라벨 정의의 논리적 검토(수명 말기에 두 예측이 함께 0으로 수렴해 δ가 사라지는 구간의 처리, 설계 시 기대와 다른 현상의 기록)를 마쳤다.

### 4.2 에이전트 설계 (v1 구현 완료)

에이전트는 매 운용 주기마다 아래 고정 파이프라인으로 동작한다.

```
주기 t 도착
  ├─ Sensor Tool : 센서 14개의 이력 → 단위 없는 통계 4종 (급변, 요동, 고착, 수준 이동)
  └─ RUL Tool    : 모델 출력 이력, MC dropout 50회 → 출력 궤적, 기울기, 급변, 불확실성 비율
        ↓
  증거 표 조립 → LLM 1회 판정 (구조화 JSON) → 코드 검증 → 기록
```

- **정보 차단.** 에이전트가 볼 수 있는 것은 배포 환경에서 관측 가능한 것만이다: 센서 값의 이력, 배포 모델의 출력 이력, 같은 모델을 dropout을 켠 채 50회 반복 실행해 얻은 불확실성. clean 예측, 정답 RUL, 오염 시점, 시나리오 종류는 차단하며, 이 차단은 자동 테스트로 강제한다.
- **도구.** 도구는 판정·임계값·센서 선택을 하지 않는다. 14개 센서 전부의 통계를 "이 설비의 평소 변동의 몇 배"라는 단위 없는 값으로 계산해 넘기고, 판단은 LLM이 한다.
- **LLM.** Qwen2.5-32B를 로컬 서버(vLLM)로 운용한다. 결정적 설정(temperature 0, seed 고정)과 프롬프트 해시 기반 캐시로 재현성을 확보한다. 출력은 저하 여부(0/1), 의심 센서, 확신도, 근거 문장이다.
- **기술 검증.** 단위 테스트 18개, 미래 데이터 접근 금지 검증, 정보 차단 검증을 통과했다. 처리 속도는 주기당 약 0.3초(동시 16)로, 전체 4,880 시나리오·약 37만 주기 판정이 하루 남짓에 가능하다.

### 4.3 평가 체계 (확정)

에이전트의 판정은 주기 단위 하나이지만, 이를 두 축으로 채점한다.

**주기 단위 (상태를 맞히는가).** 라벨 1 주기에서의 정답률(Recall)과 라벨 0 주기에서의 오경보율(FAR)을 주 지표로 하고, 데이터셋 내부 비교용으로 Precision·F1을 함께 보고한다. 오염 전 구간은 같은 설비의 모든 시나리오에서 데이터가 같으므로 (설비, 주기) 단위로 중복을 제거해 센다. 수명 말기에 두 예측이 모두 0으로 수렴해 에이전트가 관측할 수 없는 구간은 채점에서 제외하고, 제외하지 않은 결과도 병기한다.

**사건 단위 (저하 시작을 잡는가).** 오염 이후 에이전트의 첫 경보 시점 t̂이 라벨상 저하 시작 τ_d의 ±5주기 안이면 탐지 성공(TP), 그보다 이르면 Early, 늦으면 Late, 없으면 Miss로 분류한다. Detection Rate, 평균 탐지 지연(MDD), 의심 센서가 실제 주입 센서와 일치하는 비율(Isolation)을 보고한다. 저하가 없는 시나리오에서는 오염 후 한 번이라도 경보한 비율(시나리오 FAR)을 본다.

**기준선.** 항상 정상, 항상 저하로 답하는 무판단 판정기와, 단일 통계량에 임계값을 둔 규칙 판정기를 같은 표로 채점하여 에이전트가 이들보다 나은지를 확인한다.

### 4.4 예비 결과와 다음 단계

1/4 층화 표본(1,220 시나리오, 약 18만 주기)에서 v1 에이전트는 Recall 0.90, FAR 0.83, Detection Rate 0.27, 시나리오 FAR 1.00을 기록했다. F1 0.35는 "항상 저하" 기준선의 0.33과 거의 같다. 즉 **v1은 무판단 기준선과 구분되지 않았다.**

원인 분석은 명확한 방향을 준다. 설비 자기 이력만으로 만든 센서 통계는 정상과 저하를 거의 구분하지 못했다(14센서 중 최대 수준 이동이 정상 구간 1.4, 저하 구간 1.9). LLM은 근거 문장에서 이 값들을 "유의한 이상"으로 읽었다. 문제는 LLM의 추론보다 **증거의 분리력**에 있다.

같은 표본에 대한 추가 분석에서, 정상 fleet(학습용 80대)에서 학습한 센서 간 관계로 "다른 센서들이 예측하는 값"과 실제 값의 잔차를 계산하면 단독 판별력이 AUROC 0.80에서 0.91로 오르고, 오염된 센서를 14개 중 1위로 짚는 비율이 69%에 이르렀다. 설비의 열화는 모든 센서를 함께 움직여 잔차에 남지 않고, 한 센서만의 오염은 잔차에 남기 때문이다. 이 결과는 다음 단계의 핵심 개선 방향이다.

## 6. 기대 효과 및 활용 방안

**학술적 기여.** (1) 정답을 알 수 없는 배포 환경에서 예측 모델의 신뢰성을 counterfactual 기준으로 정의하고 평가하는 벤치마크와 프로토콜. 라벨 정의의 논리적 검토와 검증 절차를 함께 공개해 재사용 가능하게 한다. (2) LLM 에이전트가 통계 증거를 결합해 "센서 이상"과 "모델 저하"를 구분할 수 있는지, 어떤 증거가 그 구분을 가능하게 하는지에 대한 실증. (3) 예비 결과가 보여주듯 이 과제는 자명하지 않으며, 무판단 기준선과의 비교를 포함한 정직한 평가 관행을 제시한다.

**산업적 활용.** 예지보전 시스템에 붙일 수 있는 **모델 감시 층**이다. 기존 RUL 모델을 바꾸지 않고, 그 입력과 출력만 관찰해 "지금 이 예측을 믿어도 되는가"를 매 주기 알려준다. 경보 시 원인 센서와 판단 근거를 자연어로 제시하므로 운영자가 검증하기 쉽고, 오경보에 대한 신뢰 회복도 빠르다. 공개 데이터와 공개 모델 위에 구축했으므로 다른 설비·모델로 이전하는 비용이 낮다.

**교육적 효과.** 연구 과정에서 벤치마크 설계, 라벨 정의의 타당성 검증, LLM 에이전트 구현, 정보 차단과 재현성 확보, 평가 규약 설계를 모두 경험한다. 특히 "정답이 없는 문제를 어떻게 정의하고 평가하는가"는 산업 AI 전반에 적용되는 역량이다.
