# Bias Injection 정교화 — 왜 & 어떻게

## 0. 한 줄 정의
센서 결함(bias)을 데이터에 주입할 때, **크기를 σ로 넣던 방식을 버리고 "탐지 난이도(cons)"를 직접 목표로 잡아 자동 보정**하도록 바꿨다. 결함을 물리적으로 해석 가능한 레시피(`FaultSpec`)로 파라미터화하고, 관측 센서만 손상시키되 RUL 정답은 보존한다. (`cons` = 룰 탐지기가 실제로 보는 신호 = `temp_consistency_z_abs`.)

---

## 1. 기존 ±2σ 방식의 한계 (WHY 바꿔야 했나)

기존: unit 11의 온도 4채널(T24/T30/T48/T50)에 cycle 23부터 **±2σ 상수 스텝**을 주입.

스트레스 테스트(`stress_difficulty.py`)로 드러난 다섯 가지 문제:

| # | 한계 | 근거 (실측) |
|---|---|---|
| 1 | **크기가 너무 큼 → "공짜" 난이도** | 탐지 절벽은 ~0.4σ인데 2σ는 그 5배. FNR=0이 나오는 건 실력이 아니라 주입이 쉬워서 |
| 2 | **σ가 실제 난이도와 따로 논다** | 같은 2σ라도 채널·모드마다 체감 난이도가 제각각 → 모드 간 공정 비교 불가 |
| 3 | **급격한 스텝이라 쉬움** | ramp로 바꾸면 latency 5→17, FNR 0→0.22. 실제 센서 열화는 점진적인데 반영 안 됨 |
| 4 | **채널 subset이라 쉬움** | 전채널 bias면 consistency 관계가 보존돼 recall 0.08로 실패 |
| 5 | **결정론적 · 물리 근거 없음** | onset 23 고정 + 부호 2개뿐 → 단일 포인트 결과, 통계적 신뢰 없음. "4개 온도에 동일 σ배 오프셋"은 실제 어떤 결함 모드에도 대응 안 됨 |

→ 한마디로 **"대놓고 고장 나서 누구나 아는" 쉬운 상황**이었고, 결과(FNR=0)가 프레임워크의 실력인지 주입이 쉬웠던 탓인지 구분할 수 없었다.

---

## 2. 새 방식의 핵심 아이디어 (WHAT)

정교화의 목표는 단순히 "더 어렵게"가 아니라 네 가지를 동시에:

1. **물리적으로 해석 가능한 결함 모드** — 무엇이 고장났는지 말할 수 있게
2. **난이도를 연속 파라미터로 제어** — 탐지 절벽 주변에서 운용
3. **랜덤화된 시나리오** — 단일 포인트가 아니라 곡선·분포로 보고
4. **LLM 부가가치가 드러나는 모호성** — 룰 탐지기가 반쯤 실패하는 지점

---

## 3. 결함을 3축으로 분해 (HOW ①)

주입 하나를 `(결함 모드) × (시간 프로파일) × (채널 범위)`의 조합으로 정의 → `FaultSpec` 레시피.

### 축 1 — 결함 모드 (무엇이 고장났나)
| 모드 | 수식 | 물리적 대응 |
|---|---|---|
| offset | `x̃ = x + δ` | 캘리브레이션 오프셋 (= 기존 방식) |
| **gain** | `x̃ = x·(1+γ)` | 열전대 감도 열화 (고출력에서만 발현) |
| **drift** | `x̃ = x + δ·r(c)` | 서미스터/열전대 에이징 |
| noise | `x̃ = x + ε_t` | 커넥터 열화, EMI |
| stuck | `x̃_t = x_{t0}` | 센서/ADC freeze |
| **stealth** | on-manifold FDIA | 탐지기 회피 계측 조작 공격 |

### 축 2 — 시간 프로파일 (언제 어떻게 커지나)
step(계단) · **ramp(경사, 길이 L)** · exp(지수 포화) · intermittent(간헐→상시)

### 축 3 — 채널 범위 (어디에)
**single(T48 단독)** · temp4 · module · all14

> 근거: 이 "결함 유형 하나를 크기·시점·시간모양으로 파라미터화"하는 방식은 fault injection 분야의 표준(**What/When/Where** 모델). 특히 NASA Balaban et al. 2011의 항공우주 센서 결함 주입 방식과 동일 계보.

## 4. σ가 아니라 "탐지기 신호(cons)"로 난이도 제어 (HOW ② — 가장 중요)

> **용어 주의**: 초기엔 이 난이도 지표를 "SNR"이라 불렀으나, 탐지기 판정 통계량과 어긋난 정의였음이 실험에서 드러나(아래 7절) **`cons`(= `temp_consistency_z_abs`)로 정정·통일**했다. 이 문서에서 난이도 지표는 전부 `cons`로 표기한다.

### 발상의 전환
- **σ 방식 (기존)**: "크기를 2σ로 넣자" → 난이도는 나오는 대로 (제어 불가)
- **cons 방식 (신규)**: "난이도(cons)를 4로 만들자" → 그렇게 되는 크기를 **거꾸로 찾는다**

입력(크기)이 아니라 **출력(탐지 난이도)을 직접 지정**한다. 에어컨 온도조절기와 같은 원리.

### cons(난이도) 정의
```
difficulty := 룰 탐지기가 실제로 판정에 쓰는 통계량
   cons     = temp_consistency_z_abs  (온도 4채널 평균 consistency)
              post-onset plateau 구간 평균
```
- **왜 이 통계량?** 룰 탐지기(agent.py)는 `real_shift = (cons>3 & |regime|>5) or max_cons>6`으로 판정. 여기서 `cons`가 곧 `temp_consistency_z_abs`. **난이도는 탐지기가 실제로 보는 값에 맞춰야** 의미가 있음.
- 초기엔 "주입 채널 자체의 consistency"(당시 "SNR"이라 명명)로 정의했으나, 그건 탐지기의 판정 통계량과 정렬되지 않아(단일 채널이 4채널 평균에서 희석됨) 실험에서 문제가 드러남 → **탐지기 통계량 `cons` 기준으로 정정**.

### 보정 방법
왜곡 크기를 이분탐색으로 조절해 위 측정값(cons)이 목표값이 되는 지점을 자동으로 찾음.
(`inject.calibrate_to_detector()`)

### cons 눈금
| cons | 의미 |
|---|---|
| 1~2 | 탐지 한계 이하 (거의 못 잡음, 아주 어려움) |
| **3~4** | 절벽 부근 (반반 ← LLM이 기여하는 구간) |
| 6 | 여유 있게 탐지 (쉬움) |

**결정적 이점**: 모드·채널이 달라도(drift/gain/stealth, 1채널/4채널) "cons 4"면 탐지 난이도가 같다 → **공정한 비교**가 가능. σ로는 불가능했던 것(7절 (B)에서 입증).

### 대표 시나리오
`dataset/corrupted_NCMAPSS/unit11__T48__drift-ramp15__difficulty-cons4__onset45pct__adverse/`

**가정 상황**: unit 11의 배기가스 온도 센서(T48)가 수명 45%(cycle 27)부터 15사이클에 걸쳐 서서히 노후화 → 실제보다 온도를 **낮게** 보고 → 엔진이 건강하다 착각(RUL 과대평가, 안전 최악) → 교체 시점을 놓칠 위험. 난이도는 룰이 반쯤 놓치는 cons 4(애매 구간).

| 요소 | 값 |
|---|---|
| 대상 | unit 11 (Direction-A: 훈련과 같은 flight class 3라 "결함만 있는 깨끗한 실험") |
| 채널 | T48 단독 (실무에서 가장 흔한 EGT 열전대 결함) |
| 프로파일 | ramp, 15 cycle |
| onset | cycle 27 (수명 45%) |
| 부호 | − (adverse, 열화 은폐) |
| 보정 결과 | target cons 4.0 → **realised 4.00**, T48 −51.27 raw |

### 원칙
- **관측 센서(X_s)만 손상, RUL 정답(Y)은 불변** → "센서는 거짓말하지만 정답은 진짜"
- **train(dev) 데이터는 손대지 않음** (오염 시 실험 무의미)
- 원본과 동일 스키마 → 기존 로더가 경로만 바꿔 **드롭인 로딩**
- 원본 파일 무손상

## 6. 기존 vs 신규 한눈에

| | 기존 ±2σ | 신규 bias injection |
|---|---|---|
| 크기 제어 | σ 배수 (난이도 방치) | **cons 목표 → 크기 역산** |
| 결함 종류 | 상수 오프셋 1종 | 6+ 모드 (drift/gain/stealth…) |
| 시간 변화 | 급격한 스텝 | step/ramp/exp/intermittent |
| 채널 | 온도 4채널 고정 | single/module/all 선택 |
| onset | cycle 23 고정 | 수명 30/45/60% 랜덤화 |
| 난이도 | 2σ = "공짜" | 절벽(cons 3~4)에 정밀 배치 |
| 물리 해석 | 없음 | EGT 열전대 노후 등 명시 |
| 모드 간 비교 | 불가 | cons 정규화로 공정 비교 |

## 7. 실험 검증 (rule agent, unit 11) — `snr_experiment.py`

`figures/snr_experiment_summary.png` 참조.

### (A) 난이도 절벽은 실재하며 cons≈3에 있다
temp4 scope에서 탐지기 신호(cons)를 스윕:

| target cons | recall | FNR | latency |
|---|---|---|---|
| 1.0 | 0.00 | 0.22 | — |
| 2.0 | 0.00 | 0.78 | — |
| **3.0** | **0.45** | 0.44 | 19 |
| 4.0 | 0.64 | 0.22 | 13 |
| 6.0 | 0.73 | 0.11 | 10 |

→ recall이 cons 2→3에서 0.00→0.45로 급등. **절벽은 룰 임계값(cons>3)에 정확히 위치**하고, **cons 3~4가 애매 구간**(recall 0.45~0.64). 이로써 "절벽 부근이 애매하다"는 추정이 우리 새 방식 데이터로 **검증**됨.

### (B) σ는 난이도를 통제 못 하고, cons는 통제한다
scope 3개(single T48 / temp2 / temp4)에서:

| 방식 | single | temp2 | temp4 | recall 편차 |
|---|---|---|---|---|
| **σ 고정(0.5σ)** | recall 0.73 | **0.00** | 0.55 | **0.73** (제각각) |
| **cons 고정(cons=4)** | recall 0.73 | 0.64 | 0.64 | **0.09** (거의 일정) |

→ **같은 0.5σ인데** scope에 따라 recall이 0.00~0.73으로 요동(같은 σ가 scope마다 탐지 신호 2.07~3.84로 달라서). **cons로 맞추면** 세 scope 모두 cons=4로 정렬돼 recall이 0.64~0.73으로 일정. **난이도 통제력 8배 우위**(편차 0.73 → 0.09).
