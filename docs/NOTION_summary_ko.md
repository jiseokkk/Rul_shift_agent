# 분포이동 인식 RUL 결정 에이전트 — 왜 & 어떻게

## 0. 한 줄 정의
약한 LSTM이 잔여수명(RUL)을 예측하고, **그 위에 얹은 에이전트가 "지금 입력이 학습 분포에서 벗어났는가"를 판단해 정비 결정(continue/inspect/replace)을 내린다.** 에이전트는 예측을 고치지 않고 **얼마나 믿을지**를 결정한다.

## 1. 문제의식 (WHY)
- RUL 모델은 배포 데이터가 학습 분포에서 벗어나면 **조용히 틀린다** — 여전히 자신 있는 숫자를 뱉어 정비자가 잘못 판단.
- 이동은 두 종류인데 겉보기 신호가 같다:
  - **센서 결함/공격(adverse)**: 엔진이 건강해 보여 RUL 과대평가 → **위험(놓치면 사고)**
  - **운전조건 변화(natural)**: 다른 비행클래스라 센서값 자체가 다름 → **안전(모델은 사실 잘 일반화)**
- 기존 방법은 이 둘을 못 가른다:

| 방법 | 보는 것 | 실패 |
|---|---|---|
| Threshold | RUL 숫자 | adverse에서 부풀린 RUL 그대로 믿음 → **FNR 1.00** |
| CUSUM | 전역 z-score | z만으로 둘 다 경보 → natural **FPR 0.45** |

→ **단일 규칙으로 adverse를 잡으면서 natural을 조용히 둘 수 없다.** 이게 풀어야 할 지점.

## 2. 핵심 아이디어 (WHY)
- LLM을 **예측기가 아니라 "신뢰성 감사관"** 으로 사용 → 여러 이질 신호를 종합·추론해 결정 + 근거 제시.
- RUL 예측력은 일부러 안 건드림(약한 LSTM) → 성능이 **예측력이 아니라 신호통합에서** 온다는 걸 보이려고.

## 3. Tier-1 — 이동의 "원인"을 가르는 신호 3종 (핵심)

순진한 `z_global`("학습 평균에서 몇 σ")은 운전조건이 바뀌어도 커지고 고장나도 커져서 **원인 구분 불가**. Tier-1은 더 똑똑한 질문을 던진다.

### #1 `regime_z` — "지금 운전 방식을 감안하면 정상인가?"
- **WHY**: 다른 비행클래스는 *운전점(W)* 이 달라 센서값이 달라질 뿐, 물리 규칙은 그대로 → 운전점으로 조건화하면 자연 이동이 상쇄됨.
- **HOW**: Fc3 학습으로 `E[센서 | W]`를 **다항 선형회귀**(W=alt·Mach·TRA·T2, degree 2, 15항)로 학습 → `regime_z = (관측 − 기대) / 잔차std`. **버킷 나눔이 아니라 연속함수 조건화.** 센서 14개 각각 모델.
- 자동차 비유: "오르막+액셀"이면 RPM 4000은 정상 — 그 상황의 기대 RPM에서 벗어난 정도를 봄.

### #2 `consistency_z` — "센서들끼리 서로 말이 맞나?" (이 태스크의 주력 판별기)
- **WHY**: 엔진 물리는 온도·압력·회전수를 묶어놓음. 일부 채널만 오염되면 서로 안 맞음 / 비행클래스 변화는 다 함께 움직여 여전히 맞음.
- **HOW**: `E[센서_j | 나머지 13센서]`를 **선형회귀**로 학습 → 잔차 정규화. 온도계 4개 비유(하나만 다른 값 = 그게 고장).

### #3 `mc_std` — 모델 자신의 불확실성
- **WHY**: OOD 입력에선 예측이 불안정 → 모델이 스스로 "자신없음"을 드러냄. 센서통계와 **독립** 채널.
- **HOW**: LSTM에 dropout 켠 채 30회 예측 → 표준편차.

### 실측 — 세 신호가 실제로 갈라짐 (unit 11, cycle 30)
| 지표 | clean | adverse(−2σ) | favorable(+2σ) | natural(Fc1) |
|---|---|---|---|---|
| temp z_global (순진) | +0.31 | −1.69 | +2.31 | +0.58 |
| **regime_z (#1)** | −0.05 | **−62.5** | **+62.4** | −0.55 |
| **consistency_z (#2)** | 0.40 | **15.6** | 15.9 | 0.52 |
| RUL 편향 | 0 | **+41.9** | −23.3 | ≈0 |
| MC std (#3) | 1.68 | **4.97** | — | — |

→ 센서 바이어스 **15~62σ 폭발**, 자연 이동 **0.5~1.2σ 잠잠** → 원인 구분 성립.

> ⚠️ Tier-1 특징 추출기는 **신경망이 아니라 선형/다항 회귀(최소제곱)**. 프로젝트에서 신경망은 RUL LSTM 하나뿐.

## 4. Tier-2 — 결정 정책 (출력 다듬기)
| | 내용 | 상태 |
|---|---|---|
| #4 CUSUM 융합 | 검출기 통계를 에이전트 입력으로 | ❌ 제거 (Tier-1이 지배 → CUSUM은 순수 baseline) |
| #5 hysteresis | shift 격상을 연속 2회 지속돼야 확정 → 고립 오경보 억제 | ✅ (끄면 adverse FPR 0.18→0.27) |
| #6 cost-aware | adverse 확정 시 inspect floor / favorable은 inspect cap / 저confidence는 중간 기권 | ✅ (miss > false alarm 비대칭 반영) |

## 5. 파이프라인 (HOW, 전체 흐름)
```
HDF5 → ①특징모델 fit(regime·consistency, Fc3만) → ②LSTM 학습(val RMSE 5.65)
→ ③결정포인트 패킷 생성(바이어스 주입 + RUL+MCstd + Tier-1 특징)
→ ④베이스라인(threshold·CUSUM) → ⑤에이전트(LLM 4단계 추론 + Tier-2 정책)
→ ⑥평가(FNR/FPR/F1) → ⑦ablation → ⑧그림·리포트
```
에이전트 추론 4단계: **Step1 CAUSE GATE**(regime_z·consistency_z 작으면 shift 아님 → z 커도 무시) → **Step2 방향**(부호) → **Step3 물리**(RUL 상승점프=불가능) → **Step4 비용 반영 결정**.

## 6. 결과
| Method | no_shift | adverse | natural | shift감지 |
|---|---|---|---|---|
| threshold | 0.22/0.00/0.88 | **1.00**/0.00/0.00 | 0.06/0.00/0.97 | — |
| cusum(baseline) | 0.22/0.00/0.88 | 0.00/0.09/0.95 | 0.00/**0.45**/0.72 | F1 0.91, 지연 8 |
| **agent(LLM)** | 0.22/0.00/0.88 | 0.00/0.27/0.86 | 0.06/**0.00**/0.97 | **F1 1.00, 지연 2** |

(FNR/FPR/F1 · 값 낮을수록 좋음, F1 높을수록 좋음)
- **핵심**: 에이전트만 adverse(FNR 0)와 natural(FPR 0)을 **동시에** 이김. 단일 베이스라인 불가.
- **Ablation**: consistency 제거→adverse F1 **0.00** 붕괴 / Tier-1 전부 제거→natural FPR **0.65**(CUSUM처럼 실패).

## 7. 한계 — bias injection이 너무 쉬움 (정직하게)
스트레스 테스트 결과:
| 주입 | FNR | shift recall | latency |
|---|---|---|---|
| 0.25σ 스텝 | **0.78** | 0.00 | — |
| 2.0σ 스텝(현 설정) | 0.00 | 0.92 | 5 |
| 1.0σ **점진 ramp** | **0.22** | 0.58 | **17** |
| 전채널 0.5σ | 0.11 | **0.08** | 14 |

- 탐지 절벽 ~0.4σ인데 논문은 **2σ(5배 위)** → "공짜" 영역이라 FNR 0.
- **급격 스텝·채널 subset**이라 쉬움. 점진 드리프트/전채널이면 크게 나빠짐.
- 선형 판별기라 상수 바이어스엔 이상적이지만 **운전점 공변(co-varying) 결함엔 취약**.
- **개선**: 단일 2σ 점 → σ 스윕 탐지곡선, 점진 ramp 기본, 전채널·gain·calibration 하드케이스 추가.
- 단 2σ에서도 **베이스라인은 실패**하므로 비교는 공정. **Dir B(주입 없음)는 진짜 일반화 테스트**라 더 정직.
